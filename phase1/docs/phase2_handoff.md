# Phase 2 引き継ぎメモ（Week 11〜12）

最終更新日: 2026-05-08

## 目的

Phase 1（PDF要約・Q&Aアプリ）で得た実装結果を踏まえ、Phase 2（RAGアプリケーション）で優先的に着手する課題を整理する。

## 現状サマリ

- Phase 1では、PDFアップロード・抽出・要約・Q&A・履歴保存までを実装済み。
- Q&Aは「先頭5チャンク投入」で動作し、簡易 citation（`chunkId` 単位）を返せる。
- 認証は `x-user-id` ヘッダーによる暫定方式であり、本番運用には不十分。

## Phase 2 優先バックログ（推奨順）

### 1) 検索基盤のRAG化（最優先）

- `document_chunks` に対する embedding 生成・保存を実装する。
- pgvector 導入後、`match_document_chunks` 等の検索RPCを追加する。
- 現在の「先頭Nチャンク投入」を段階的に置換し、質問ごとの関連チャンクのみを投入する。

**Done判定**
- 同一質問に対して、関連チャンク上位K件（例: K=5）が取得される。
- 回答生成プロンプトが検索結果のみを参照する。

### 2) citation の精度向上

- `document_chunks.page_start` / `page_end` の活用を強化し、回答の出典ページをUI表示する。
- `chunkId` だけでなく、引用テキスト断片（quote）を抽出して保存する。
- 「根拠なし」の判定基準をプロンプトとアプリ双方で統一する。

**Done判定**
- 回答ごとにページ番号付き citation が返る。
- 無関係質問時は固定メッセージを安定して返す。

### 3) 認証・認可の本番化

- `x-user-id` 暫定認証を廃止し、Supabase Auth（JWT検証）へ移行する。
- `documents` / `sessions` のアクセス制御を user_id ベースで厳格化する。
- RLS（Row Level Security）ポリシーを設計・適用する。

**Done判定**
- 未認証リクエストは拒否される。
- 他ユーザーのセッション・文書にはアクセスできない。

### 4) 評価運用の定量化

- `docs/qa_evaluation_log.md` の評価軸に「citation正確性」「再現率」を追加する。
- 手動評価に加え、回帰用の固定質問セットをテストとして自動化する。
- プロンプトバージョンと評価結果の紐付けを必須化する。

**Done判定**
- PR時に最低限の回帰テストが走る。
- 品質劣化時に差分を説明できる。

### 5) 監視・運用整備

- APIエラー率、平均応答時間、429率、タイムアウト率を可視化する。
- 重要イベント（upload失敗、embedding失敗、検索0件）を構造化ログで出力する。
- 障害一次切り分け手順（Runbook）を作成する。

**Done判定**
- 主要KPIのダッシュボードを確認できる。
- 障害時の一次対応フローがドキュメント化されている。

## 技術的負債（Phase 1残）

- OCR非対応（画像PDFは対象外）。
- ストリーミング経路のE2Eテストが不足。
- 429応答時のRetry-After秒数がUIに未表示。

## Phase 2 スコープ外（当面見送り）

- 高度な reranking（cross-encoder など）
- ハイブリッド検索（keyword + vector）の最適化
- マルチテナント監査ログの完全整備

まずは「検索の成立」と「根拠表示の信頼性」を優先する。
