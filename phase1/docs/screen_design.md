## チャット画面（上限超過状態）UIラフ

```
┌─────────────────────────────────────────┐
│  ← 戻る    large_sample.pdf             │
├──────────────┬──────────────────────────┤
│              │                          │
│  要約        │  チャット                 │
│  ──────────  │  ──────────────────────  │
│  この文書は  │  ⚠ このPDFはPhase 1の     │
│  ○○につい   │    Q&A上限を超えていま     │
│  て述べてい  │    す。要約のみ対応しま     │
│  る。主な    │    す。                    │
│  ポイントは  │                          │
│  以下の通り  │  AI: このPDFはPhase 1の   │
│  ・・・      │  上限を超えているため、    │
│              │  Q&Aに対応していません。   │
│  [コスト表示]│                          │
│              │  ┌──────────────────┐   │
│              │  │ 質問入力は無効化  │   │
│              │  └──────────────────┘   │
│              │  [送信不可]              │
└──────────────┴──────────────────────────┘
```

- 表示文言は固定で `このPDFはPhase 1のQ&A上限を超えています。要約のみ対応します。` を使用する。
- 上限超過の判定はアップロード完了時に実施し、該当セッションではQ&A入力UIを初期表示から無効化する。

## APIエラー表示ルール（画面/API契約の同期）

`phase1/docs/api_contract.md` の共通エラーコードUI表示ルールと同一の挙動を採用する。

| error.code | 表示文言（固定） | 再試行可否 | 入力欄disable |
|---|---|---|---|
| `BAD_REQUEST` | 入力内容に誤りがあります。内容を確認してください。 | 不可（入力修正後に送信） | なし |
| `PAYLOAD_TOO_LARGE` | 入力サイズが上限を超えています。短くするか対象を絞ってください。 | 不可（入力修正後に送信） | なし |
| `RATE_LIMITED` | リクエストが集中しています。しばらく待ってから再試行してください。 | 可（待機後に再試行） | あり（一定時間） |
| `INTERNAL_ERROR` | サーバーエラーが発生しました。時間をおいて再試行してください。 | 可（時間をおいて再試行） | なし |

## チャット画面の根拠表示UIとDB項目の対応

### UIイメージ（追記）

チャット欄のAI回答直下に、根拠表示ブロックを追加する。

```
AI: PDFの3ページ目によると、〇〇とは...

[根拠]
- p.3-4 「......（該当箇所の抜粋）......」
- p.8 「......（該当箇所の抜粋）......」
```

### 対応するDBフィールド（Phase 1採用方式）

- AI回答本文: `messages.content`
- 根拠メタ情報（採用）: `messages.citations`（JSON）
  - 例: `[{ "chunk_id": "...", "page_start": 3, "page_end": 4, "quote": "..." }]`
- 文書名表示（ヘッダー）: `documents.filename`

### 実装メモ

- Phase 1では `citations`（JSON）を唯一の根拠表示データソースとする。
- 画面側は `citations` を直接パースし、`page_start`/`page_end`/`quote` を表示する。
